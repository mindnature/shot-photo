# GPT Image / Images 2.5 Prompting Guide

Shot Photo 默认主要服务 GPT Image / Images 2.5。

## 1. 核心原则

Images 2.5 更适合“简洁但准确的摄影导演指令”，不需要把所有摄影变量都穷尽式写进 Prompt。

优先写清楚：

1. 谁在画面里；
2. 人在哪里；
3. 正在发生什么；
4. 摄影师以什么距离与关系观察；
5. 一个核心构图亮点；
6. 一个核心光线亮点；
7. 必要时一个真实感线索。

不要把 Prompt 写成逗号标签仓库，也不要把后台规划字段逐项抄进去。

> 一个好 Prompt 应该像摄影师给助理的简洁拍摄说明，而不是一张包含所有参数的检查表。

---

## 2. Images 2.5 Prompt Compression

内部可以完整规划：

```text
scene
moment
expression
wardrobe
shot size
lens
camera position
composition
foreground
lighting
palette
imperfection
```

但最终 Prompt 不需要全部显式出现。

### 一张图最多突出

- 1 个主要构图亮点；
- 1 个主要光线亮点；
- 1 个空间层次线索；
- 0–1 个摄影缺陷。

其他摄影关系如果已经能被上下文自然推导，就让 Images 2.5 自己完成。

---

## 3. Standard Prompt 模板

推荐自然语言结构：

```text
[画幅 / 图片类型]。
[主体]在[场景 / 时间]，[正在发生的瞬间]。
摄影师以[观察关系 / 距离]记录，重点采用[一个构图亮点]。
光线来自[一个真实来源]，[必要时补一个颜色或空间线索]。
[可选：一个真实摄影状态]。
避免影楼式精修、塑料皮肤、过度摆拍和无理由杂乱背景，保持真实可信的生活摄影感。
```

通常 100–240 个中文字足够。

### 示例

```text
9:16 竖幅真实生活摄影。一位短发中国女生在广州盛夏午后的老城区便利店门口，刚推门出来，走了两步后被热风吹乱头发，抬手正要别到耳后。摄影师从街对面中距离观察，让人物偏在画面右侧，左侧保留旧墙与街道空间。侧后方夏日硬光落在头发和肩膀上，白墙提供自然反光。保留一点手持即时感。避免影楼式精修、塑料皮肤和标准网红摆拍。
```

---

## 4. Random Strong Prompt 模板

Random Strong 要比 Standard 更短、更开放。

```text
[画幅]真实手机 / 生活摄影。
一位[主体]在[随机子场景]，[进行中的动作]。
从[观察关系]拍到这一瞬间，画面重点是[一个构图亮点]。
使用[一个真实光线来源]，保持颜色简单可信。
让它像偶然拍到的真实照片，而不是标准人像模板。
```

通常 70–180 个中文字。

### 示例

```text
9:16 真实手机照片。一位素颜大学生在校园食堂端着餐盘刚转过身，似乎有人在旁边叫她。摄影师站在排队人群边缘近距离记录，让餐盘和周围学生形成自然空间层次。食堂冷白灯混合窗外日光，保持普通校园生活的颜色和质感。像朋友随手拍到，不要精修摆拍感。
```

---

## 5. Random Wild Prompt 模板

Wild 只锁用户真正要求的内容，其余尽量让模型发明。

```text
[画幅]真实生活摄影。
为[主体]在[宽泛场域]创造一张意外但可信的照片。
使用一个不常见但合理的子场景、观察距离和机位，捕捉未完成动作。
让构图有明显个性但物理上可拍到，光线只来自现场真实环境。
保持日常可信，不要变成商业写真。
```

Wild 可以保留一个明确的随机结果（例如“操场看台远距离侧拍”），但不要把所有随机结果都再写成硬约束。

---

## 6. Anchor Budget

### Standard

- Hard Anchors ≤ 4
- Soft Anchors ≤ 4
- Free Variables ≥ 4

### Random Strong

- Hard Anchors ≤ 3
- Soft Anchors ≤ 3
- Free Variables ≥ 6

### Random Wild

- Hard Anchors ≤ 2
- Soft Anchors ≤ 2
- Free Variables ≥ 8

当不确定某个细节是否必须写进 Prompt 时：

- Standard：如果会明显改变照片身份，可以写；
- Strong：优先不写；
- Wild：除非用户明确要求，否则不写。

---

## 7. 抽象词要转译，但不要过度翻译

### “高级感”

优先翻译成其中 1–2 项：

- 色块克制；
- 背景干净但真实；
- 人物动作克制；
- 单纯光源；
- 明显负空间。

不要五项全部塞进一张图。

### “电影感”

优先从以下选 1–2 项：

- 明暗关系；
- 人物和摄影师距离；
- 未完成动作；
- 现实光源；
- 前后空间层次。

不自动等于橙青调、烟雾、轮廓光。

### “抓拍感”

优先：

- 动作未完成；
- 人物没有服务镜头；
- 摄影师不是标准正面位；
- 画面边缘有真实环境关系。

不要只写 `candid`。

### “松弛感”

优先：

- 身体重量有依靠；
- 动作不是展示姿态；
- 视线不服务镜头；
- 构图不追求绝对对称。

---

## 8. 负面约束

Images 2.5 不需要长 negative list。

默认一句：

```text
避免影楼式精修、塑料皮肤、过度摆拍和无理由杂乱背景，保持真实可信的生活摄影感。
```

Random Wild 甚至可以进一步缩短为：

```text
保持真实生活摄影，不要商业写真感。
```

不要机械重复：真实、超真实、照片级真实、自然真实、纪录片真实等同义词。

---

## 9. Controlled Imperfection

不要靠“加噪点”解决 AI 味。

默认 0–1 个摄影状态即可：

- 轻微运动模糊；
- 边缘物体进入画面；
- 小范围高光溢出；
- 轻微玻璃反射；
- 很轻的手持即时感。

只有明确需要时才允许 2 个。

真实感优先来自：

```text
动作
+ 空间
+ 摄影师位置
+ 真实光线
```

而不是噪点、颗粒、失焦的堆叠。

---

## 10. 同一人物系列

只有用户明确要求“同一个人 / 一套写真 / 连续组照”时才强调身份连续性。

Series 中：

- 重复人物最稳定的 3–5 个身份点；
- 若有参考图，优先使用参考图身份；
- 不每次重新发明脸型、年龄、发型和服装体系；
- Prompt 只需要一句简洁连续性约束，不要每张重复长篇五官描述。

Random Strong / Wild 默认不继承上一张身份。

---

## 11. 参考图改造

用户给照片时优先提取摄影关系：

- 人物占比；
- 摄影距离；
- 机位高低；
- 可能焦段区间；
- 前景 / 中景 / 背景；
- 主光方向；
- 主要色块；
- 动作阶段；
- 真实感来源。

除非用户要求复刻，否则迁移关系，不复制全部物件。

Reference + Random 时只锁 2–4 个最高置信摄影 DNA，其余继续随机。

---

## 12. 最终判断

提交 Prompt 前问三个问题：

1. 摄影师为什么站在那里？
2. 为什么恰好在这一秒按下快门？
3. 我是否写了太多 Images 2.5 本来就能自己完成的细节？

前两个答不出来：摄影逻辑不足。

第三个答案是“是”：删掉约束，而不是继续加词。
